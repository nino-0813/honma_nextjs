# ストア分析：KGI・KPI

既存 `/admin/analytics` を拡張。別の管理ページは追加しません。既存の認証・注文・契約・在庫の更新処理は変更しません。

## 見方

- 上段：集計年（日本時間の1/1〜12/31）ごとのストア全体売上、年間目標・達成率・残り金額。お米の年産販売期間とは別の暦年です。
- 中段：「今月／過去7・30・90日／過去1年間」の売上、新規購入者、定期便新規登録、解約記録。上段の年とは独立し、対象日付を明示します。
- 下段：月別売上、人気商品トップ5、同じ年産のお米の販売・確保（玄米kg・常に参考値）。注文管理・在庫管理へのリンクを配置。
- 平均注文額・購入者数・現在の継続中契約・期末解約予約・登録商品数・全期間注文レコード数も表示。

## 集計定義・制限

1. 売上は `payment_status=paid` の注文total（税込・送料込）。キャンセル注文は除きます。全額返金でrefundedになった注文も除外。部分返金額・原価・会計上の税抜売上は本画面では計算しません。
2. `paid_at` を優先し、未記録のみ `created_at` へフォールバック。対象数を「集計条件」に表示します。未来日付・不正日付は集計しません。
3. 新規購入者は、当該期間に対象の支払済み注文を持つ顧客のうち、全取得履歴の初回支払が期間内の人。メールをtrim/小文字化して識別し、メールがない場合はauth_user_idで補完。unknown@example.com等の識別不能注文を人数に入れません。過去の返金済み購入も既存顧客の判定履歴として使用します。
4. 定期便新規登録はcreated_atが期間内で、現在statusがincomplete/incomplete_expiredではないレコード数。初回入金日や契約開始イベント数ではありません。現在の状態が変わると過去期間の値も変わり得ます。
5. 解約記録は `canceled_at` が期間内の現存契約数。期末解約予約・自動解約を含み、実際の終了日とは限りません。取消・再開等の完全なイベント履歴は未保存です。Stripe仕様参照：[Subscription object](https://docs.stripe.com/api/subscriptions/object)。継続中は現在active/trialing/past_due/paused、期末解約予約はmetadata.cancel_at_period_endの現在値です。
6. 粗利益実績、継続率、お試し→定期便移行率は、原価・イベント履歴・母集団定義が未整備のため「未集計」。推定値を実績として表示しません。
7. 人気商品はline_totalを数値化して合計し、注文数は商品ごとのorder_idを重複排除。削除商品でproduct_idがnullなら商品名で分離します。商品明細合計と注文totalは税・送料・割引等で差が出ます。
8. 在庫は既存kg_reportのv2台帳のみ使用し、連動停止・旧重量版・年産未登録は数字を出しません。初期量未登録なら負の差引きも参考表示し、販売可能量と断定しません。未判定の注文や契約は在庫管理で確認してください。
9. 注文・明細・契約・目標は正確なcountとページングで全件取得。サーバー側のページ上限がリクエストより小さくても続けて読みます。件数不明・中断時は集計を出しません。読み取り中の同時更新に対するDBスナップショット固定は行っていません。
10. 注文読取失敗はページ全体をエラーにし、0売上を表示しません。明細・契約・在庫・目標の失敗は個別に未取得として扱います。権限で参照不可の行は集計できないため、既存の管理者用RLSが前提です。

## 年間目標の保存を有効にする（本番では未実行）

`migration_add_analytics_yearly_targets.sql` をSupabase SQL Editorで一度だけ実行します。実行前に、対象プロジェクトと `select to_regclass('public.analytics_yearly_targets');` の結果を確認してください。すでにテーブルがある場合は再実行・削除せず、構造を確認します。

追加テーブルは年間売上・粗利益の目標だけです。RLSで管理者profiles.is_adminのみSELECT/INSERT/UPDATE可能、匿名・非管理者の読み書きとDELETEは不可。注文・契約・在庫への変更はありません。実環境での管理者/非管理者のRLS動作検証はSQL適用後に必要です。

SQL未適用時も注文集計は動作しますが、目標は「未取得」、保存は無効です。適用後に「最新に更新」を押してください。空欄は未設定（NULL）、目標は1円以上の整数で入力。入力値はブラウザのlocalStorageへ保存せず、DBから読み直します。保存失敗時は入力を残して再試行できます。
