## 読み取り変換

`lib/externalOrderSheets.ts`：実際の列に合わせた副作用のない読み取り変換。
日付・整数数量・重量・品種・精米区分・年産・状態を確認し、識別子と要確認理由を返す。
注文番号＋商品＋精米＋重量を暫定キーにし、数量や金額変更で別注文に増殖させない。
同じ商品が同じ注文に複数行ある場合は合算せず、明細IDがなければ要確認。
明細IDは確定後に使用。行番号を識別子にしない。行削除をキャンセルとみなさない。

変換関数自体は副作用なし。下記の受付APIから使用する。まだ自動連携は稼働していない。

## 受付とGAS（ローカル実装・本番未接続）

- `scripts/gas/external-sheet-sync.gs`：既存2冊の設定済みタブを読み取る独立GAS。元シートを変更せず、住所・氏名・備考を送らない。Gmail取込の既存GASを上書きしない。
- `app/api/external-sheet-sync/route.ts`：送信元ごとの秘密キー、登録済みブック/タブID、時刻、行数・サイズ・セル型を検証。
- `migration_add_external_sheet_staging.sql`：最新スナップショットと変更履歴を保存。ソース単位のDBロックで並行送信を直列化。同一内容は履歴を増やさず、古い読取時刻は拒否。
- キー・DB接続がない場合は停止。初期値はdry-runで保存なし。保存モードでも**取込用データのみ**、EC注文・在庫・紹介精算を変更しない。
- 同じキーが2行にある場合や識別不能行も、上書き・合算せず要確認として全体を保存。行の削除をキャンセルと判定しない。
- 全タブ最大5,000行／送信2MB。超過時は分割せず停止し、全件重複検出を維持。大量データ用の分割確定プロトコルは未実装。
- 管理者だけ取込データを参照可能、書込RPCはservice_role限定。管理画面への取込一覧表示と在庫台帳への接続は未実装。

設定・テスト手順は `docs/external-sheet-sync-setup.md`。

1. 各媒体GASが追加列をどう設定するか。過去行の有効状態・年産は推測で補完しない。明細IDは作成後不変とし、既存の仮キーからの切替には照合が必要。
2. 椎茸は2026-10-20営業前18個と確認済み。目標18個とは分離し、同日の売上から差し引く。管理画面で基準を後から変更可能にした（追加SQL・本番接続は未実施）。基準日以前の履歴を二重減算しない。
3. ふるさと系の「売上」が寄付額、税込商品代金、手数料控除後の入金額のどれか。
4. 紹介還元には紹介者ID・商品売上・送料・商品値引き・返金日と商品返金額を対応づける必要がある。
5. 顧客は氏名だけで同一人物と判定しない。外部顧客IDや確認済みの紐付けが必要。
6. 欠けた数量は1個と仮定しない。年産は注文年月から推測しない。
