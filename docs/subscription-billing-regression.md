# 初回発送前のサイクル変更と0円請求書

## 原因と修正

`invoice.paid` / `invoice_payment.paid` が `subscription_update` の請求書まで注文として複製していました。
さらに `amount_paid` が0だと金額上書きの条件を通らず、元注文の金額が残っていました。
その結果、Stripeの管理上の0円請求書から有料の「支払済み」注文が作られていました。

- 新規の継続注文は `billing_reason=subscription_cycle` に限定。
- 初回・契約変更・日割り調整の請求書からは発送注文を作らない。
- 理由や総額が不明な請求書は503を返し、注文を推測して作らない。
- 注文総額には `invoice.total` を使う。顧客残高や割引で支払額が0でも、実際の継続発送は別物なので一律除外しない。

サイクル変更APIは従来、価格の配送周期のみを差し替え、初回発送を基準に請求日を指定していませんでした。
初回発送前の月単位変更では `trial_end` を「初回発送月＋新しい周期の10日05:00 JST」に設定します。
例：初回2026/11/15、2か月ごと → 次回請求2027/1/10 05:00、次の発送1/15。
初回発送日そのものは変更しません。商品と送料の数量も維持します。
初回発送後のサイクル変更・スキップの全体仕様を作り替える変更ではありません。

参考：Stripeの[サブスクリプション更新仕様](https://docs.stripe.com/api/subscriptions/update)では、
周期を変えると `proration_behavior=none` でも請求基準日が変わり得ます。
`trial_end` は請求基準日にも反映されます。

## 既存データの復旧（未実施）

コード反映だけでは既存契約の請求日・誤注文は修復されません。
本番Stripeに接続できる状態で、次を一件ずつ確認して対応します。

1. 上記請求書の理由・金額・PaymentIntent/Chargeを照合し、実課金がないことを確認。
2. 初回11/15が既決済・未発送であり、現在も2か月周期であることを再確認。
3. 対象契約だけの `trial_end` を2027/1/10 05:00 JST（UTC 2027/1/9 20:00）へ、日割りなしで変更。
4. Webhook同期後にDBの次回請求日と初回発送が一致していることを確認。
5. 誤注文は削除ではなく理由付き取消として監査履歴を残す。実課金がないため返金しない。
6. 誤注文によるSKU在庫減算・kg台帳・マイル・外部GAS通知への影響を確認し、重複補正を避けて訂正。
7. 初回注文や契約自体をキャンセルしない。誤注文を取り消す操作と契約解約は別。
