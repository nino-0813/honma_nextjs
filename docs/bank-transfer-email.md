# 銀行振込の案内メール

## 修正内容

従来はBrevoの銀行振込受付テンプレートへStripeの案内URLのみを渡していました。
口座情報を直接表示するテンプレートでは、口座名義・番号・銀行・支店・種別が空になります。

銀行振込受付メールに限り、本文をアプリ側で組み立てます。
Stripeの `next_action.display_bank_transfer_instructions.financial_addresses` の `zengin` から
口座情報を取得し、普通・当座を日本語表示します。口座番号は文字列のまま扱います。
StripeのHTTPS案内URLがある場合は「振込先を確認する」リンクも表示します。

イベントに口座情報またはリンクが不足している場合はPaymentIntentを再取得します。
再取得後にリンクのみ取得できた場合は、空の口座欄を作らずリンクで案内します。
口座情報も有効なリンクもない場合はメールを送らず503を返します。
メール送信失敗時もイベント記録を解放して503を返し、Stripeの再試行を受け付けます。
在庫確保は解放せず、既存の確保済みチェックを維持します。
入金済み・返金済み・注文キャンセル済みの注文は古い振込案内イベントで戻しません。

カード決済・入金確認メールのテンプレートは変更しません。追加SQLは不要です。

## 送信元の設定

`BREVO_FROM_EMAIL` / `BREVO_FROM_NAME` がある場合はそれを使用します。
ない場合は `BREVO_BANK_TRANSFER_ORDER_TEMPLATE_ID`（未設定なら8）の送信元を
Brevo APIから読み取り、認証済みの送信元として再利用します。
テンプレート本文やBrevo管理画面の設定は変更しません。
送信元を取得できない場合はメール送信を失敗扱いにして再試行を要求します。

## 本番反映後の確認

1. 振込案内メールの名義・口座番号・銀行・支店・種別がStripeの案内ページと一致すること。
2. 「振込先を確認する」リンクが開くこと。
3. 注文金額・注文番号・支払期限が一致すること。
4. カード注文には銀行振込受付メールが送られないこと。

自動テストは外部接続をモックし、お客様へのメール送信・本番決済を行いません。
すでに空欄メールを受け取ったお客様への再案内は別途必要です。
過去の成功扱いイベントを自動再送する変更は含みません。
メール事業者が受理した直後に通信が切れた場合など、再試行による重複送信の可能性は残ります。
